Anthropic 发了一篇 Claude Code 口述史。

我觉得它最有价值的地方，不是告诉我们 Claude Code 有多强，而是把一个 coding agent 怎么被产品化讲清楚了。

核心判断很简单：

模型是发动机，产品化靠 harness。

Claude Code 的关键，不只是 Claude 会写代码，而是把模型放进真实工程环境：shell、文件系统、测试反馈、权限确认、上下文搜索、自动更新、用户反馈。

为什么 coding 会成为 Agent 的第一块硬地？

因为代码天然有闭环：命令能运行，测试会失败，diff 能 review，日志能返回证据。这让 Agent 不只是聊天，而是可以行动、验证、修正。

为什么是 CLI？

因为 terminal 是工程动作发生的地方。git、测试、日志、包管理、脚本、部署都在这里。Agent 要进入软件工程，最短路径不是重做一个漂亮 UI，而是站到已有工具链里。

这篇给我的启发是：以后项目能不能用好 coding agent，不只取决于模型能力，也取决于项目本身有没有上下文、验证路径和权限边界。
