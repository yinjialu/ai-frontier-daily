# 专题深度线设计（第三条内容线）

**日期**: 2026-06-24
**状态**: 待实现（首篇 Claude Tag + 流程定型）

## 背景与目标

用户（公众号「变量生活」）的内容输出现有两条线：
- **早报**（ai-frontier-daily/daily）——时效性，每日 AI 大厂动态卡片。
- **内参**（firsthand）——官方一手动态小时级监控。

新增第三条线 **专题深度**：对一个值得深挖的功能点（如今天的 Claude Tag），向**普通用户**深度介绍——是什么、功能详解、官方案例整理+翻译、实操截图/录屏（视可体验情况）、作者点评。

**核心约束（标尺）**：克制、高质量、稳定、及时——与前两条线一致；外加**输出导向**（最终落到公众号成稿）。

## 架构

```
内参 data/firsthand/index.json + 早报
      ↓ ① 选题初筛（新）—— AI 标"值得深挖"候选
   用户选定一个题（如 Claude Tag）
      ↓ ② 专题深度骨架生成器（新）—— 生成 draft.md（五段骨架 + 官方素材 + 待补充项）
      ↓ ③ article-harness（复用）—— Writer ↔ Reviewer 迭代成稿
   用户只审核 → 反馈
      ↓ ④ 反馈沉淀进 reviewer.md（已有机制）
   content-pool/drafts/<topic>/draft.md → 公众号发布（wechat-official-draft skill）
```

## 组件设计

### 1. 选题初筛（新）
扫内参 `data/firsthand/index.json`（Feature B 产物）+ 早报，按"深挖价值"标候选：
- **优先**：模型发布、重大新功能（如 Claude Tag）、范式级研究。
- **过滤**：例行公告、版本号小更新、纯政策/人事。
- 输出候选清单给用户选；**用户初筛标准 → 我选 → 流水线生产**（用户语）。
- 实现：可作为 `firsthand-digest` skill 的一个子能力，或独立小脚本读 index.json 打"深挖候选"标。

### 2. 专题深度骨架生成器（新）
对选定题目，生成 `draft.md`，**五段骨架 + 待补充项标记**（供 article-harness 的 Writer 填充润色）：

| 段 | 内容 | 来源 |
|----|------|------|
| ① 一句话是什么 | 向普通用户说清这是什么 | 内参 OKF summary + 官方原文 |
| ② 功能详解 | 解决什么痛点 / 怎么用 / 关键限制 | 官方原文整理 |
| ③ 官方案例整理 + 翻译 | 官网/博客 use case 整理并译为中文 | 抓官方 blog/docs/案例页 |
| ④ 实操截图/录屏 | 可体验 → 占位"待补"；不可体验 → 标"暂不可体验" | 用户手动 / 或 browser 自动 |
| ⑤ 作者点评 | 变量生活视角（可选） | 用户 |

- 抓取官方素材复用内参的 adapters（html-links/article text）+ WebFetch 翻译。
- 输出落 `content-pool/drafts/<date>_<topic>/draft.md`（与现有 drafts 同构）。

### 3. reviewer.md 专题深度维度补充
专题深度有特有质量点，随首篇反馈沉淀进 `article-harness/reviewer.md`（已有机制）：
- **官方案例翻译准确**：不误译、不夸大、保留官方限定词。
- **对普通用户友好**：不堆术语，先讲"对用户意味着什么"。
- **占位标注清楚**：截图/录屏未补时明确标注，不留空段冒充完成。

### 4. 输出
`content-pool/drafts/<topic>/` → 人工终审 → `wechat-official-draft` skill 排版发布。
