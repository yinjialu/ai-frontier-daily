# 专题深度 → 小红书发布 设计

**日期**: 2026-06-24
**状态**: 待实现

## 背景与目标

专题深度长文成稿后，除了公众号，还要发**小红书图文**。早报已有成熟的小红书链路（卡片渲染 + xiaohongshu-mcp 发布 + 移动端发布页），**复用它**，不另起炉灶（拆独立 skill 是过度设计）。

新 skill `deepdive-xiaohongshu`（放 `ai-frontier-daily/skills/`）：把专题深度成稿**稳定**转换为适合小红书的图文卡，复用现成渲染/发布栈。**核心是"长文 → 小红书图文"的稳定转换**。

## 架构

```
content/deepdive/<slug>/draft.md (+ assets/cover*.png)
   ↓ ① AI 卡片脚本（新）—— 成稿 → xhs.json
   ↓ ② 渲染（复用 render.js 引擎 + 新增「深度知识卡」版式）→ output/deepdive/<slug>/*.png
   ↓ ③ 发布（复用 publish_xhs_newspic.py + publish.html 扩展）→ 移动端快捷指令 / xiaohongshu-mcp
```

**复用 vs 新增：**

| 环节 | 复用现成 | 新增 |
|------|---------|------|
| 卡片脚本（长文→短卡） | — | ✅ skill 指令 + 硬约束 + 校验脚本 |
| 卡片版式 | `render.js` 引擎（Playwright，1080 宽，card→图） | ✅ `cards.js`/`cards.css` 加「深度知识卡」 |
| 封面 | — | 用文章已有封面图（小黑），无则文字封面卡 |
| 发布 | `publish_xhs_newspic.py`（xiaohongshu-mcp）、`publish.html`（快捷指令 UX） | ✅ publish.html 加深度内容入口 |

## 组件设计

### 1. AI 卡片脚本（核心，"稳定"所在）
skill 指令：读成稿 markdown → 产出 `xhs.json`：
```json
{
  "slug": "introducing-claude-tag",
  "cover": "assets/cover-xiaohei-agent-identity.png",   // 文章已有封面图相对路径；无则 null
  "title": "Claude Tag：给 AI 发工牌",                    // ≤20 字（平台硬限）
  "cards": [
    {"heading": "AI 不再「代表你」", "lines": ["以前它借你的权限行事", "现在它有自己的账号"]},
    {"heading": "权限从 per-user → per-channel", "lines": ["…"]}
  ],
  "caption": "…",                                        // 笔记正文 ≤1000 字（平台硬限）
  "tags": ["AI", "Claude", "Agent"]
}
```
**改写而非照搬**：每张卡是一个要点、口语化、短。**硬约束**：标题 ≤20 字、caption ≤1000 字、每卡 heading ≤14 字 / 每行 ≤22 字 / ≤4 行、cards 4~8 张。
**校验脚本** `scripts/deepdive/xhs_validate.py`：检查 xhs.json 是否满足上述硬约束，超限报错（防止生成阶段就溢出）。

### 2. 深度知识卡版式（cards.js / cards.css）
在 `skills/ai-daily-digest/cards.js` 加一个 `deepdiveCards(DATA)` 构建器：给定 xhs.json，输出 render.js 要的 card 对象数组（`{name, cls, w, h, inner}`，cls 用 `.card.deepdive`）：
- 封面卡：用 cover 图 / 或大标题文字封面。
- 知识卡：heading + lines，干净版式（白底或淡色、克制、移动端可读）。
`cards.css` 加 `.card.deepdive` 样式（1080×1440，留白、字号适配）。**不动早报现有卡片版式**（纯追加）。

### 3. 渲染（复用 render.js）
`render.js` 不改——它已能吃 card 数组逐个截图。新增一个薄入口 `scripts/deepdive/render_xhs.js`（或复用 render.js 的 `--data` 路径），把 xhs.json 经 `deepdiveCards` 喂给 render.js 引擎，输出 `output/deepdive/<slug>/NN-*.png`（1080×1440 PNG）。

### 4. 发布（复用）
- **移动端**：`publish.html` 加「深度内容」入口/Tab，列 `output/deepdive/<slug>/` 的图 + caption，复用现有「📲 发送到快捷指令 / 🔗 复制文案 / ⬇️ 打包 zip」。
- **自动发（可选）**：`publish_xhs_newspic.py` 已走 xiaohongshu-mcp；为深度内容加一个素材入口或参数，复用其发布逻辑。

## 数据流

```
draft.md ──①AI──> xhs.json ──validate──> ②deepdiveCards ──③render.js──> output/deepdive/<slug>/*.png
                     │                                                         │
                  caption/tags ─────────────────────────────────────> ④publish.html / publish_xhs(xiaohongshu-mcp)
```

## "稳定"机制（重点）

1. **生成期硬约束**：卡片脚本 schema 限定字数/卡数；`xhs_validate.py` 不过线就报错，不进渲染。
2. **渲染期溢出自检**：渲染后检查卡片高度/文字是否溢出 1080×1440；超了回退（缩短行/拆卡/降字号），保证每张图都规整。
3. **平台硬限内建**：标题 ≤20、正文 ≤1000、图片 ASCII 路径（复用 publish_xhs 已有处理）。

## 不在范围内

- 不拆独立 skill / 不放 bianliang-skills（在本仓复用）。
- 不重写渲染/发布引擎（复用 render.js / publish_xhs / publish.html）。
- 不做封面图自动生成（封面用文章已有小黑图，或文字封面卡；小黑出图仍交 Codex）。
- 不改早报现有卡片版式（深度卡纯追加）。
